# 00 — Project Context

## Project

The Bradbury Group platform rebuild.

## Current state

The current site is a WordPress-based marketing site with generic navigation and limited automation. The new platform should move beyond a simple website redesign and become a CMS-driven business platform that supports lead capture, content publishing, AI readiness assessment, CRM automation, and later agentic workflows.

## Why this rebuild exists

The goal is not just visual redesign. The MVP should:

- Replace generic Training / Speaking / Consulting navigation with journey-led product architecture
- Let Paige's team publish and edit pages, blogs, resources, case studies, FAQs, and testimonials without developer help
- Capture leads from forms, gated resources, Columbus conversations, and AI readiness assessment flows
- Send structured lead data into HubSpot, ClickUp, and email/nurture systems
- Prepare a clean foundation for Phase 2 learning platform and Phase 3 agent fleet

## Source architecture inputs

The implementation should reconcile:

- TBG 45-Day MVP Platform Plan
- Website Content Architecture draft
- Social Content Knowledge Graph positioning rules
- Solomon Engine pitch and product architecture
- AI Operational Blueprint / Augmentation Advantage deck direction

## Core product navigation

Approved direction unless stakeholder overrides:

- Home
- AI Fluency Cohort
- The Solomon Engine / Walter for L&D
- For Organizations
- Our AI Return
- Resources
- About
- Insights
- Contact / Book a Discovery Call

## Key naming distinctions

- `The Solomon Engine` = 12-week executive program
- `Solomon` = AI assistant delivered inside / after the program
- `Columbus` = public site assistant / routing widget
- `Walter` = L&D strategist track / assistant reference
- `AESOP` or `AI Readiness Assessment` = unresolved naming decision

Do not use Solomon and The Solomon Engine interchangeably.
